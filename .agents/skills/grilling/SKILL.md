# 烤问（grilling）

"烤"不是否定，是**在花用户时间之前，先让方案自己撞一遍墙**。撞得过的问题答案会落盘；撞不过的那个问题，就是这次真正的风险。

## 0. 谁烤谁

- **先烤自己**：能从代码、文档、`git log`、跑一条命令得出答案的，不许拿去问人。
- **再烤用户**：只剩"这条我猜不出来"的问题才开口。一次 1–3 个，每个都带默认答案与理由。
- **不烤已经定了的**：`AGENTS.md` 的不变量、`ROADMAP` 里 accepted 的决定、用户这轮已经明确说过的话 —— 再问一遍等于让他重复劳动。

## 1. 通用的七刀

按这个顺序过，每刀给自己一句话的答案；答不上来的那刀就是风险：

| 刀 | 问题 | 答不上来意味着 |
| --- | --- | --- |
| 目标 | 做完之后，**用什么命令 / 什么画面**判定它成了？ | 目标不可判定，做完谁也不认 |
| 反例 | 什么情况下它**不该**生效？现在这条路径判得出来吗？ | 只有 happy path |
| 数据 | 用户会不会因此丢东西（布局、对话、key、未提交的工作）？ | 一次意外调用就删用户数据 |
| 并发 | 两条同时跑会怎样？第二次点击会怎样？ | 重复窗口 / 丢写 / 按钮永久变灰 |
| 失败 | 网断了、权限撤了、文件坏了、组件崩了，分别长什么样？ | 静默失败，界面显示"检查你的网络" |
| 回滚 | 发出去之后发现不对，怎么退回上一版？ | 没有退路 |
| 证据 | 我这次的"验过了"，是哪几条命令的哪几行输出？ | 没验，只是看过 |

## 2. 这个仓库专属的三刀

- **不变量**：这次改动碰的是第几条？碰了就要按那条的四五条"别踩回去"逐条对（`invariants` skill 按"我要动什么"查）。
- **一份事实只有一个家**：这个判据现在住在哪个文件？我是改它，还是在旁边新开一个（新开 = 以后两处互相骗）。
- **门禁到位没**：`typecheck` / 相关断言页 / `check:docs` / `rust` job —— 哪条会红？红了我知道为什么红吗？

## 3. 烤出来之后怎么办

- **答得上的**：写进提交说明或设计稿一行 —— 那是"为什么这么做"的证据。
- **答不上的，且属于本次范围**：先修，别交付。
- **答不上的，且超出范围**：写进 `AGENTS.md` 第 8 节的缺口表（影响 + 需要的动作），交付时明说。
- **需要用户拍的**：一次问完，带默认答案。

## 4. 什么时候别烤

- 用户在等一件明确的小事（改一句话、跑一条命令）—— 烤一遍比做完还慢。
- 已经烤过一轮、答案没变 —— 重复拷问只会把预算花在同一处。
- 讨论阶段还没决定要不要做 —— 先定目标（`define-goal`），再烤方案。

## 5. 一条底线

**"我看了一眼，应该没问题" 不是答案。** 说"验过了"必须能给出：哪条命令、哪几行输出、红了会是什么样。给不出就把那句话改成"没验，因为……"—— 后者至少不会骗下一个人。

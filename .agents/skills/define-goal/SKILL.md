# 定目标

一句话进来，先把它变成**能被判定成败**的东西，再动手。目标里出现"完善""优化""更好看""再稳一点"这类词，说明它还没定 —— 那种词没有判据，做完谁也不认。

## 0. 五要素

| 要素 | 长什么样 | 反例 |
| --- | --- | --- |
| **objective** | 一句，动词 + 对象（"把 `shell.open` 撤权限后的提示补齐"） | "把桌面体验做好" |
| **done-when** | 能红的命令、能看见的画面、能对账的数字 | "应该差不多了" |
| **non-goals** | 这次**明确不**碰的地方 | 不写 → 顺手改了别的模块 |
| **禁手** | 这个仓库不许做的动作（`git add -A`、`reset --hard`、改别人的未提交文件、勾 pre-release） | 靠"我记得" |
| **stop** | 什么时候停下来问，而不是自己决定 | 做完才发现方向错了 |

`done-when` 至少有一条是**机械的**：`npm run typecheck` 绿、某断言页 N 条全过、`check:docs` 绿、安装包能装、某个命令输出对得上。只剩"我看了一眼觉得行"，就不算定完。

## 1. 长活才建 goal

- **跨多轮、有后续自动继续**：`create_goal` 存一条，objective 用上面那句，别把 done-when 写进 objective（那是判据，写进正文或文档）。
- **一轮能做完**：不建。建了只是多一个要维护的状态。
- **做完就 complete**：目标不是"进度条"，达成了不收尾，下一轮还会围着它转。
- **被卡住要 blocked**：同一个阻塞条件连续三轮没变才标 blocked，并在 `blocked_reason` 里写那个具体条件 —— 难度和不确定性不算。

## 2. 先自己查，再问人

能从这里查到答案的，不占用用户的时间：

| 问题 | 先查 |
| --- | --- |
| 这件事现在做到哪 | `AGENTS.md` 第 8 节缺口表、`ROADMAP` 进度表 |
| 这一步该按什么顺序 | `.agents/skills/`（`invariants` / `verify` / `new-widget`） |
| 这个词指什么 | `GLOSSARY.md` |
| 以前踩过吗 | `docs/PITFALLS.md`（搜症状） |
| 之前怎么决定的 | `docs/ROADMAP.md`「被推翻的九个决定」、`docs/design/` |

查完还剩的真歧义，一次问 **1–3 个**，每个都带上**我的默认答案 + 理由**："我打算按 A 做，因为 B；除非你要 C。" —— 别问"你想怎么办"。

## 3. 目标里必须写清的三个边界

1. **不碰什么**（别的会话正在改的文件、`docs/` 之外的用户文件、`v0.1.1` 已发出去的产物）。
2. **不许做的事**（见上面"禁手"列）。
3. **什么算完**（机械判据 + 一句人话）。

## 4. 中途要改目标

- 用户改主意 → 重写 objective（别在旧的上面叠注），旧目标要么 complete 要么 edit。
- 发现方向错了 → **停下来说**，别默默加范围。加范围之前先问：这属于你刚说的那件事吗？

## 5. 收尾

- `done-when` 逐条打勾，每条后面写**证据**（命令、输出摘要、文件路径）。
- 没做到的写进"已知缺口"，别写成"基本完成" —— 那是把没验的东西伪装成验过的。

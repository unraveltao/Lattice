# 0016 —— 给没提交代码的人记一笔

## 1. 问题

一个人给了建议，被采纳了，他一行代码都没写。于是仓库里没有任何痕迹：`git log` 里没有他，
GitHub 的 Contributors 图里没有他，一年后你翻到那段设计，想不起来是谁点醒的 —— 而他自己
也不会记得当初提过什么。

不做这件事的坏结果不是"不够礼貌"，是**这段设计变成无主之物**：下一个人看到它，只能看到
"当初就是这样"，看不到"因为有人说了一句什么，才不是另一个样子"。项目里那些被推翻的决定
（`ROADMAP` 里记着 9 个）恰恰是最需要来源的部分。

## 2. 候选

| | A：什么都不做 | B：`CONTRIBUTORS.md` | C：`CREDITS.md` + 不用 `Co-authored-by` | D：提交时挂 `Co-authored-by:` |
| --- | --- | --- | --- | --- |
| 做法 | 只在 commit 里口头提一句 | 建一份 `CONTRIBUTORS.md`，把提建议的人列进去 | 建 `CREDITS.md`，一条 = 名字 + 改了什么 + 落在哪；不用 trailer | 代提交时在 message 里写 `Co-authored-by: 他`，GitHub 会把他算进 Contributors |
| 换掉什么 | 无 | 无 | 无 | 无 |
| 新增什么 | 无 | 一个文件 | 一个文件 + 一条入档判据 | 一个文件都不用，图上直接有人 |
| 代价 | 来源永久丢失 | 文件名的字面意思被违反：`contributor` 在 GitHub 上有确定含义（提交过代码的人），名单里大多数人不是 | 图上仍然没有他们；要维护一条判据 | **署名造假**：代码是你写的，GitHub 却记成共同作者 |

D 是唯一能"同时满足两边"的方案，所以它一定会被提出来 —— 也正因为它看起来最省事，才要写在这里。

## 3. 决定

选 C。

`contributor` 是一个**由提交定义**的词，不是"帮过忙的人"的同义词。用 B 会把两件事压成一个词，
结果是两边都失真：真提交过代码的人被稀释，提建议的人被误读成"他写过这块"。改个文件名就
能避免的歧义，没必要留成债。

D 被否掉不是因为它无效 —— 它非常有效，这正是问题。它用一句 trailer 换掉了一条真实记录：
谁写了那几行。这个仓库里"每一条不变量背后都是一个发出去过的 bug"，署名也一样，掺一次假，
以后就没法用"GitHub 上是这么写的"当证据了。

**代价**：那些人不会出现在 Contributors 图上。愿意动手的，可以自己提一个 PR 把自己加进
`CREDITS.md` —— 那是真实提交，图上就真有他（前提是那条提交的作者邮箱是他自己的、且挂在他账号上；
PR #1 那两条的作者是 `pending@localhost`，合并了也不会出现）。这条记在本文件第 5 节，**不写进
`CREDITS.md`** —— 那份文件只记名单和判据，一旦开始教怎么提交代码，它就变成了另一份
`CONTRIBUTING.md`，而且是会过期的那份。

**什么时候该推翻它**：如果这个项目开始有**外部代码贡献者**（真的提交 PR 的人），并且他们
要求一份"谁写了什么"的正式名单，那就该换成 `CONTRIBUTORS.md` + 一份 `AUTHORS`，把代码贡献
和非代码致谢**分成两个文件**，而不是合成一个。到那时 `CREDITS.md` 里那一节搬过去即可，
判据不用改。

第 4 节（接口与数据）整节省略：不落盘、不加命令、不改桥，`CREDITS.md` 是一份纯文档。

## 5. 失败模式

| 症状 | 原因 | 正确行为 |
| --- | --- | --- |
| 名单里的人说"我不记得同意过" | 挂上去之前没告诉本人 | 写进去之后告知一声；他说撤就撤，不问理由 |
| 名单越来越长，谁都不好意思删 | 没有入档判据，或者设了"重要程度"门槛 | 只有一条硬判据：能指出一处"因他而改"的东西。指不出来就不进；不按贡献大小排序 |
| 有人问"为什么他不在 Contributors 图上" | 两条通道被混为一谈 | 指向本文件第 3 节；`CREDITS.md` 开头只留一句指向这里，不解释 |
| 合并了 PR，头像还是没出现 | 提交的作者邮箱是 `pending@localhost` 这类占位地址，没绑任何账号 | GitHub 认的是 `author email`，且要在他账号的已验证邮箱里。让他用自己的邮箱提交一次，`user.name` 改成什么都不管用 |
| 名字张冠李戴，或者写错了改了什么 | 凭记忆写 | 一条记录必须能顺着"落在哪"找到那处改动；找不到就不写 |
| 有人提议"顺手加个 `Co-authored-by` 吧" | 看起来能同时满足两边，且没有成本 | 那是署名造假。**只有他真写了那段文字或那几行代码**时才用 trailer，否则走 `CREDITS.md` |

## 6. 验收

没有断言：这一份是文档，没有代码路径可以钉。

**手工核对一条**：随便挑名单里的一条，只看"落在 `路径` / `ADR 编号`"那一句，能不能在三步之内
翻到那处改动。翻不到的，说明这条记录不合格 —— 要么补上落点，要么删掉。

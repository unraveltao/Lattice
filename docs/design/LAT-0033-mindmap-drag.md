# LAT-0033 —— 思维导图的节点可以拖（摆位）

## 1. 问题

0022 立了这条规矩：**位置是算出来的，树里没有坐标**。它换来三件事 —— 改一次从属关系不用挪任何东西、agent 不用编造坐标、同一份大纲跑两次出来的图一模一样。

但它也换来一件坏事：**自动布局摆出来的位置不合你的意时，你没有任何办法**。420×300 的卡片里，五个叶子的间距是 28px，某个分支的父节点被推到子树的垂直中点、可能离它真正相关的那一支很远；你只能折叠、缩放、平移，或者改结构骗布局。用户的原话是"每个小标题都可以拖动"。

**坏结果**：为了把两个框拉开一点，得去改大纲的层级 —— 用内容去迁就排版。

## 2. 候选

**位置怎么记**（这张表决定其余一切）

| | A：偏移叠在自动布局上（选中） | B：绝对坐标，和 diagram 一样 | C：不记，只在本次会话有效 |
| --- | --- | --- | --- |
| 做法 | `offsets: { n3: [dx, dy] }`，`layout()` 把算出来的位置加上它 | 每个节点带 `x` / `y` | 拖动只改内存，重开回到自动布局 |
| 换掉什么 | —— | 自动布局退场 | —— |
| 新增什么 | 一个归一化函数、`layout` 多一个可选参数 | 加节点要人指定位置 | 什么都不用存 |
| 代价 | 加了兄弟节点之后底会往下推，被拖过的跟着自己的底一起走 | `Alt+↑↓` 换位置之后所有坐标全错；agent `draw` 之后图散在屏幕外 | 每次重开都白拖，用户会以为拖动没生效 |

**连线怎么办**

| | A：两端贴住框（选中） | B：端点冻结，框从线上脱开 |
| --- | --- | --- |
| 读起来 | 谁挂在谁下面一眼看得出来 | 线的末端指向空白，图在说谎 |
| 实现 | 什么都不用做 —— 现在的贝塞尔就是两端算出来的 | 要额外把端点坐标存下来 |

## 3. 决定

**决定**：A + A。**偏移**（不是坐标）叠在自动布局上，连线跟着框走。

**"连线保持不动"的两种读法**：用户原话是"连线保持不动"。按字面（B）实现，框挪走之后线留在原地指向空白 —— 那正好毁掉这个组件存在的理由（0022 §1：diagram 的毛病就是"结构只存在于看起来像里"）。按"别因为我挪一个框就把整张图重排"读（A），是这个需求的最小表达。**取 A**，并明确一条：**拖动只改位置，不改结构** —— 不会因为拖到另一个框上就改挂靠关系（那是 0022 留给 v1.1 的另一件事）。

**代价**（具体）：

- **图不再完全确定**。同一份大纲在两台机器上、或者一个人拖过一个人没拖过，出来的图不一样。0022 §4 那条"同一份大纲跑两次一模一样"从此只管**没被拖过的节点**。agent 和测试都不能再假设"大纲 → 唯一一张图"。
- **加了兄弟节点，被拖过的节点会跟着底一起挪**。这是偏移的定义：`位置 = 自动位置 + 偏移`。不想要这个的人，要的是绝对坐标（B），而 B 会让 `Alt+↑↓` 之后所有坐标错位。
- **可以自己把图弄乱**。允许重叠、允许拖出视口。出路是撤销（一次拖动 = 一步），不是自动纠正 —— 自动纠正会和"只有被拖的这一支动"直接冲突。
- **偏移按 id 存，所以 `draw` 必须清空**。`draw` 整张替换并重新编号 `n1..nN`，不清空的话 A 的摆位会贴到 B 身上。`append` 相反：它不动已有 id，偏移全部保留。

**什么时候该推翻它**：常态出现"拖了三十个节点之后想要的其实是另一张图" —— 那时该做的是拖到框上改挂靠（结构编辑），不是继续优化摆位；或者卡片常态大于 800×600，那时自动布局的"不合意"会少很多，摆位可以退成可选。

**被推翻的**（同一次设计里改过主意的）：

- "吸附做成一颗开关按钮" → **按住 `Alt` 临时取消**。底栏在 280px 宽时已经装满了（0022 §6 有断言钉着），而吸附是常态、微调是例外 —— 例外用修饰键，比给常态腾一颗按钮省地方。
- "拖完加一颗「全部重排」" → **不加**。底栏在 280px 宽时已经装满了（0022 §6 有断言钉着），而 `Ctrl+Z` 50 步够用。
- "版本号升到 2" → **不升**。`normalizeDoc` 见到不认识的 `version` 就 `trusted: false`，界面显示"读不出已保存的图"且一个字节都不写 —— 升版本等于把所有人现有的图当场变成"读不出"。`offsets` 做成**可选字段**：老代码读到会忽略它（显示自动布局），新代码读到没有它的旧文档就当没摆过。
- "`draw` 之后按 id 保留偏移" → **清空**。见上面的代价第三条。

## 4. 接口与数据

**桥方法 / Tauri 命令**：**一个都不加。** 拖动是纯前端的，落盘还是 `storage.set`。

**落盘格式**（`version` 仍然是 `1`）

```json
{
  "version": 1,
  "root": { "id": "n1", "text": "Project", "collapsed": false, "children": [] },
  "view": { "x": 0, "y": 0, "zoom": 1 },
  "offsets": { "n3": [12, -28] }
}
```

- 只记**被拖过的**节点；`[0,0]` 不写；空的时候写 `{}`。
- 归一化（`normalizeOffsets`）：只留这棵树里真的有的 id、只认两个有限数、`±4000` 夹住、取整。丢掉不认识的 id 不是洁癖 —— `draw` 换过树之后那些 id 指向别的节点。
- `±4000` 是量出来的上限：200 个节点 × 28px 行高 = 5600 高的图，再远就不是"挪开一点"而是"扔了"。

**布局**

```
layout(root, { measure, row, colGap, pad, nodeH, offsets })
  → { nodes: [...], links: [...], bounds: { x, y, w, h, minX, minY }, rows }
```

- 每个节点的最终位置 = 自动位置 + 自己的偏移；`center` 也跟着偏移（文字的基线、左边那个小方点、连线的端点全读它）。
- **连线不用改**：端点本来就是从两个节点的几何算出来的，节点偏了端点就跟着偏。
- `bounds.w` / `bounds.h` 仍然是**右沿 / 下沿**（0022 的断言按这个钉的）；新增 `minX` / `minY` 记左沿 / 上沿 —— 拖到原点的左上角会出负数，`fitView` 要靠这两个值才不会把那个节点切在屏幕外。

**手势**

- 在框上按下 → 选中（立刻，和以前一样）；**移动超过 4px** 才算拖动。4px 是"别把抖动当拖拽"的常规阈值，而这个尺寸下节点在屏幕上可能只有 26px 宽（缩到 40% 时），两段式（先选中再拖）会更容易被当成"点了没反应"。
- 拖动时把同一个位移写给它**和它的所有子孙**（整支跟着走）。含根节点 —— 所以拖根 = 把整张图挪位。
- 纵向吸到 `28` 的整数倍，按住 `Alt` 不吸。吸的是**结果的偏移**而不是这一次的位移：底本来就在行上，吸结果才会让"拖三次"和"拖一次"落在同一格。横向不吸 —— 节点宽度是量出来的（64–220），横向本来就没有一条公共的线可以对齐。
- `Esc` 取消这一次拖动（偏移退回按下前的样子，不进撤销栈）；`pointercancel` 同样处理。
- 一次拖动 = **一步撤销**，在 `pointerup` 时才压栈。
- 拖完如果那个框**整个**出了视口，把视图挪回来（压到边不算）。

**要改的文件**

- `public/widgets/lattice.mindmap/mindmap-core.js`：`offsets` 的归一化 / 克隆 / `layout` / `subtreeIds` / `shiftOffsets` / `bounds.minX,minY`
- `public/widgets/lattice.mindmap/widget.js`：拖动手势、`draw` 清偏移、`withRoot` 保住 offsets
- `public/widgets/lattice.mindmap/style.css`：`is-dragging` 的抓手光标
- `public/widgets/lattice.mindmap/manifest.json`：0.1.0 → 0.2.0、`help` 补一条、`changelog`
- `tests/mindmap.html`（纯逻辑）、`GLOSSARY.md` 加「摆位」

## 5. 失败模式

| 症状 | 原因 | 正确行为 |
| --- | --- | --- |
| 打开时图显示"读不出已保存的图"，其实文件是好的 | 为了让摆位能存而把 `version` 升到 2 | 版本号不动，`offsets` 是可选的；`normalizeDoc` 只认 `1` |
| 拖完 A，agent `draw` 之后 B 跑到了 A 的位置 | `draw` 重新编号 `n1..nN`，旧偏移按 id 贴到了别的节点 | `draw` 清空 `offsets`；`append` 保留 |
| 加了一个兄弟节点，被拖过的那个跟着往下挪了 | 偏移是叠在自动位置上的 | 这是定义，不是 bug。写进 `help`：想钉死在原地，得靠绝对坐标（B），而 B 会让换位置全乱 |
| 单击选中变成"拖了一像素"，双击改名变成拖动 | 没有移动阈值 | 4px 阈值；`dblclick` 在拖动结束后 300ms 内不响应 |
| 拖到左上角之后按「适应窗口」，那个框被切掉一半 | 包围盒只记了右下沿，负坐标没算进去 | `bounds.minX/minY`，`fitView` 按跨度算 |
| 缩到 40% 时拖动一格要拖好几下 | 吸附按世界坐标的 28px，40% 时一格只有 11px 屏幕距离 | 这是对的（对齐的是行，不是屏幕）；想微调按 `Alt` |
| 拖出去再也找不回来 | 不设边界 | 拖完整个出视口时把视图挪回来；兜底是「适应窗口」 |
| 两棵树合并之后有两个节点共用 id，偏移互相打架 | `attachSubtree` 按**节点数**编号，不按最大 id（删过节点的树会撞） | 改成按最大 id 编号（顺手修，`nextIdFor` 同一套扫描） |

**手工验一次**：桌面上拖一个带三个子节点的分支（整支跟着走）→ 松手 → `Ctrl+Z` 退回 → 再拖一次按 `Esc` 中途取消（位置弹回）→ 关窗重开还在 → 让 assistant `draw` 一张新图（摆位清空）→ `append` 一支（摆位还在）→ 缩到 40% 拖一下（吸附的是行）→ 按住 `Alt` 拖（不吸）。

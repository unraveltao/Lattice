# LAT-0038 —— 给待办分三层（`lattice.todo` 0.3.0）

## 1. 问题

一张平铺列表把三件成熟度完全不同的事混在一列：还没想清楚的念头（"也许该学 Rust"）、这阵子要推进的目标（"把简历改完"）、今天必须做的事（"给房东打电话"）。它们在列表里长得一模一样，唯一的区别是你自己记不记得哪条是哪条。

**坏结果**：攒到 15 条以上，默认 280×240 的卡片里只露得出 **4.6 行**（`.todo` 内边距 24 + 标题栏 22 + 输入框 34 + 两道 8px 间距，剩 144px ÷ 31px 一行），而"今天要做的"可能在第 12 行。用户每天打开卡片要先滚一遍、读一遍才能挑出真正要动手的——**于是它退化成一张记不住的便签**。

还有一件现在做不到的事：一件事从念头长成目标、再拆成动作，中间没有痕迹。用户只能删了重打，或者把文字改掉——原来那句"想学 Rust"就没了。

## 2. 候选

**层是什么意思**

| | A：具体化程度（选中） | B：上下挂靠 | C：时间视野 |
| --- | --- | --- | --- |
| 做法 | 每条一个 `level`：1 想法 / 2 目标 / 3 执行；升格 = 改这个数字 | `parentId` 树，L3 挂在某个 L2 下、L2 挂在某个 L1 下 | 每条打三个时间标签（季度 / 本周 / 今天），三档是视图 |
| 换掉什么 | 一张列表 → 三条平行列表 | 同 A，另加一层父子关系 | 不换列表，换的是筛选方式 |
| 新增什么 | 一个字段 + 页签 + 升格手势 | 缩进、展开态、孤儿规则（删父项、跨父拖动） | 三个标签 + 三个筛选器 |
| 代价 | **看不见"这条执行服务于哪个目标"**；一次只看一档 | 280 宽缩进三级后只剩约 200px 放字；要五条孤儿规则；和 `lattice.mindmap` 那棵树重复 | **"升格"这个动词消失**——一条待办同时属于三层，只剩筛选 |

**三档怎么排**（240 高里：内边距 24 + 标题 22 + 输入 34 + 间距，剩 144~178）

| | A：三段堆叠 | B：手风琴（一次展开一档） | C：页签（选中） |
| --- | --- | --- | --- |
| 三档同时可见 | 是 | 只有标题 | 只有计数 |
| 当前档能放几行 | 每档约 1.5 行 | 3 行 | **3.7 行** |
| 代价 | 每档都挤成一行，等于没分 | 想对比两档要来回点 | 看不见另外两档的内容 |

## 3. 决定

**决定**：A（具体化程度）+ C（页签）。

理由，按证据：

- 用户描述的动词是「**变成**」——想法想清楚了变成目标，目标拆开变成执行项——不是「属于」。A 的 `level` 承载这个动词，B 的 `parentId` 承载的是"属于"。
- 240 高只够三四行。C 把 178px 全给当前那一档；A 要拿 54px 给三个段标题，B 要再加一行。
- 迁移是零成本的：老数据形状不变，只是每条多一个数字，不需要造父节点（B）也不需要补三个标签（C）。

**代价**（具体）：

- **一次只能看见一档**。另外两档压成页签上的两个数字，想总览要点两下。这是换 3.7 行付的钱。
- **跨档拖动失去落点**。目标档不在视野里，所以换档不能只靠拖：行尾 `×` 换成 `⋯`，菜单三项（升格 / 降格 / 删除）。**删除从 1 下变 2 下**；拖到页签上松手作为快捷手势保留，但它只能教一次就会，不能当唯一入口。
- **想法层没有勾选框**。一个想法只有两个出口：变成目标，或者删掉。"想法完成了"没有意义；给它勾选框，用户会拿它当"归档"，这一档很快退化成第二个待办列表。
- **页签吃掉一行**。4.6 行 → 3.7 行（页签行 22px + 一道 8px 间距）。行高不能压：13px 字 + 1.45 行高是 `style.css` 头注释里定过的，12px 的中文笔画会粘。
- **老数据全部落进 L3**，升级后"想法 / 目标"两档是空的。不是 bug，但用户会以为数据丢了。
- **schema 变了**：`widget-data/lattice.todo.json` 多一个字段（见 §4）。

**什么时候该推翻它**：用户反复手动在文字里写"为了 X"，或者明确要求"点开一个目标看它底下所有执行项"——那时加**可选**的 `parentId`（只在 L3 上有意义），A 是它的子集，老数据不用动。反过来，如果一个月后统计 `level: 1` 长期为 0，那是三档太多，退回两档。

**被推翻的**：

- 「层级」这个词 → **不用**。`GLOSSARY.md:29` 已经把它定义成窗口 z 序的三档（`desktop` / `normal` / `top`）。文档里写「层」，三档在界面上就叫 **L1 / L2 / L3**。
- 「三档 = 红黄绿」→ **不是**。优先级圆点是另一个轴，0.2.1 就有，这次一个字节都不动：一条 L3 的执行项照样可以是红色。
- 「抬默认尺寸到 300×320，三段堆叠」→ **不做**。卡片高度有两份来源（`placements[].h` 和 `desktopRects[].h`，见 PITFALLS「画布正好、桌面切掉半行」），为布局动所有老用户的窗口尺寸，代价大于收益。卡片本来就能手动拉高。
- 「L1/L2/L3 只是显示名，内部仍叫想法/目标/执行」→ **不做**。两个名字就是两套词，`GLOSSARY` 里只能留一套；界面上写 L1/L2/L3，含义放在标题栏那条里（见 §4）。

## 4. 接口与数据

**桥方法：一个都不加。** 只用现有的 `storage.get` / `storage.set`（`bridge.ts:300`）。

**权限**：不变，仍然只有 `storage`。

### 落盘（键 `items`，形状向后兼容）

```json
[
  { "id": "1761…", "text": "给房东打电话", "done": false, "priority": "high", "level": 3 },
  { "id": "1761…", "text": "也许该学 Rust", "done": false, "level": 1 }
]
```

- `level` ∈ `1 | 2 | 3`。**认不出来一律当 3**（缺失、脏值、老数据），写法和现有的 `readPriority`（`widget.js:104`）同构：认不出就当没设，不抛、不猜。
- **惰性迁移**：读的时候补默认值，**不主动重写文件**。PITFALLS 那条「组件内容被换成种子数据」就是主动重写撞出来的——读失败 ≠ 没有数据。
- `done` 在 L1 上没有意义：**读进来是 `true` 也保留**（降回 L3 时还看得见），只是 L1 不画勾选框。

### 页签状态（键 `view`）

```json
{ "level": 3 }
```

缺省 3。**按 widgetId 存**，所以画布上那张卡和桌面上那张会跟着一起切档——同一份清单本来就该长一个样，和 `store-changed` 同一个语义。认不出来当 3。

### 界面（280×240 的预算）

```
┌────────────────────────────────┐
│ L3 · 执行 · 还剩 5 项  [窗饰120]│ 22px，padding-right: 120px
│ [L1] [L2] [L3]                 │ 22px，页签
│ ────────────────────────────── │
│ ○ 给房东打电话            ⋯   │ 行 31px（30 + 1 缝）
│ ● 查水表                  ⋯   │
│ ○ 转账                    ⋯   │
│ [ 加一条 L3                  ] │ 34px
└────────────────────────────────┘
```

- **22px 那条只放计数与当前档含义**，不放组件名：`WIDGET_SPEC §5.1` 说那条写的是"此刻"的东西，名字平台标题条上已经有了（`lattice.anki` / `lattice.calculator` 已经按这条改过）。可用宽度 `280 - 24 - 120 = 136px`；窄到 240 以下时这一格整块隐藏（`@media (max-width: 239px)`）——56px 里它只剩一个「L」，既没说明什么又把计数挤瘦，那时候"是哪一档"由页签高亮负责。
- **页签写 `L1 / L2 / L3`**，三颗 `flex: 1 1 0` 均分一整行（不是各定 48px）：最窄 200 时行宽 176px，每颗约 57px，放得下 "L3"；宽的时候也不会缩成三颗小胶囊挤在左边。
- 输入框 placeholder 跟着当前档走：「加一条 L3」，提交后插到**当前页签**顶部。
- `⋯` 菜单三项：升格 / 降格 / 删除。顶档的"升格"和底档的"降格"**灰掉而不是消失**——位置稳定才点得准。
- 菜单**放不下就往上收，不整个翻到行上方**：卡片只有 240 高，翻上去会盖住页签，而换档正是从这个菜单发起的。
- 空态按档各说各的：「还没有 L1 · 想法」，不复用「还没有待办」。
- **`minH` 从 140 抬到 170**。这不是"改尺寸"，是补一个自己撞出来的窟窿：四层元素（标题 22 + 页签 22 + 输入 34 + 三道 8px 间距 + 24 内边距）在 140 高时只给列表留 **14px**，一行都放不下。170 让它回到 0.2.1 的 44px（1.4 行）。老用户已经摆好的窗口不会被改，他们自己拖一下就回到新地板。

## 5. 失败模式

| 症状 | 原因 | 正确行为 |
| --- | --- | --- |
| 升级后清单只剩几条，"想法/目标"两档是空的 | 老数据全落 L3，那两档本来就空 | 不是 bug：空态写「还没有 L1 · 想法」+ 一句"老待办都在 L3"，help 里也写 |
| 在 L1 页签按回车，条目跑到 L3 | 落点写死成 3，没读当前页签 | 落点只认当前页签；断言钉住"切到 L1 加一条，落盘那条 `level` 是 1" |
| 升格之后那一条**从眼前消失**，用户以为删了 | 它去了另一档，当前列表里当然没有 | 目标页签的计数闪一下（`is-bumped` 600ms），条目插在目标档顶部 |
| 拖一条到页签上松手，什么都没发生 / 顺手把它勾掉了 | 抬手后那次 `click` 没被吃掉；或者页签命中算在 `pointerup` 里而不是 `pointermove` | 复用现有 `suppressClick`（`widget.js:396`）；页签高亮在 `pointermove` 里算，松手只读高亮状态 |
| 另一张卡片突然自己换了页签 | `view` 按 widgetId 存，`store-changed` 把它同步过来了 | 设计如此；help 里说明。要各看各的，得换 id 装第二份 |
| 点过三行的 ⋯ 之后，三份菜单一起留在屏幕上 | `openMenu` 建完菜单忘了 `menuEl = el`，于是 `closeMenu()` 永远在 `if (!menuEl) return` 早退，谁也没删 | 建完立刻记账（`widget.js` 的 `openMenu`）；`tests/todo-levels.html` 钉住"DOM 里恰好 1 个 `.todo-menu`" |
| 切页签时列表闪一下空白 | 切档走了一次 `reload()` 重读磁盘 | 切档只重画不重读：`render()` 按 `items.filter(level)` 就地过滤 |
| 计数写「还剩 0 项」但那一档明明有 3 条没做完 | 计数用的是全局 `items`，没按当前档过滤 | 计数 = 当前档里 `!done` 的条数；L1 没有 done，计数 = L1 总条数 |
| 写盘失败后页签切不动 | 切档也走了 `persist()`，失败把界面卡在错误态 | `view` 写失败只影响"下次重启回到哪档"，内存里照样切；错误仍然只在 22px 那条说「未保存」 |
| 拉到 200×140 时页签被挤成两行、输入框看不见 | 页签行没设 `flex: none`，或字比 11px 大 | 三颗 48px + 两处 6px = 156px ≤ 176px；行高固定 22px、`flex: none`、`min-height: 0` |

## 6. 验收

| 文件 | 条数 | 钉住什么 |
| --- | --- | --- |
| `tests/todo-levels.html` | 41 | `readLevel` 认脏值/缺失一律 3；惰性迁移（读一次不写盘）；L1 无勾选框但 `done: true` 不被抹掉；落点跟当前档；升格/降格改 `level` 而不是删了重加（`id` 和优先级不变）；顶档升格灰、底档降格灰；DOM 里只许有 1 个菜单；拖到页签换档；`view` 认不出来当 3；第二个实例打开就在上次那档 |
| `tests/todo-add.html` | 29（**不改**） | 现有提交路径、桥超时、`store-changed` 重读，一条都不许红 |

**手工验一次**（真机 `npm run tauri:dev`）：

1. 手工造一份 0.2.1 的老数据（`widget-data/lattice.todo.json` 放 5 条没有 `level` 的），升级后确认全在 L3、一条不少。
2. 卡片投到桌面，确认 22px 那条的计数**不被右上角窗饰压住**（窗饰 120×28，而且能点）。
3. 拉到最小 200×170，看页签不换行、输入框还在、列表还剩一行。
4. 画布一个实例、桌面一个实例，切页签看两边是否同步。

# 0008 —— 在组件里画一张能改的图（`lattice.diagram`）

## 1. 问题

桌面上没有"一张能改的图"。想给人讲清组件怎么落到桌面上 —— 五个框、三条线 —— 现在只有三条路：开 draw.io 画完截图（改一个框就得重开外部工具）、拿嘴说、或者干脆不画。贴图片也不行：图片改不了，而且得先有图片。

**坏结果**：讲一遍要重画一遍；桌面上的图永远停在截图那一刻。

## 2. 候选

| | A：卡内画布（选中） | B：图形即 placement | C：卡内 + 只让设计画布能画 |
| --- | --- | --- | --- |
| 做法 | 组件内部就是图面，图形是它自己的 SVG 元素 | 平台新增"图形"这一层，每个图形是一个 placement | 设计画布上图形是 DOM，桌面上还是整块卡片 |
| 换掉什么 | 平台的 placement 模型不动 | `Placement` 类型、z 序、拖动、缩放、撤销、`state.json`、agent 动作白名单全部从"组件"泛化到"图形" | 无 |
| 新增什么 | 一个官方组件 | 平台层一个新对象类型 + 两套渲染入口 | 两套渲染 |
| 代价 | 一张图 = 一个窗口；图放不进卡片时只能缩放，不能"窗口就那么大" | 桌面上**一张 30 个框的图 = 30 个真窗口**（`runner.rs` 一个 placement 建一个 `WebviewWindow`），各有焦点和 DWM 开销 | 同一个 bug 改两遍，"画布上画的"和"桌面上看到的"会不一致 |

## 3. 决定

**决定**：A。需求单位是"一张图"，不是"一堆能单独拖的窗口"。

**代价**（具体）：

- 一张图占一个窗口，所以"图很大"只能靠缩放，不能靠把窗口拉大。
- **没有系统剪贴板导出、没有文件保存** —— 沙箱是 `allow-scripts allow-forms`，没有 `allow-downloads`。图要出去只能截图，或者以后加一条导出桥方法。
- 同一个实例可以同时在画布和桌面上活着（共用 `instanceId`），两边同时改会后写赢。

**什么时候该推翻它**：当"图形要能被单独拖动、单独被 agent 引用"或者"图要跨窗口拼起来"成为真需求时。那时要做的是平台层的图形对象（B），不是在这个组件里加把劲 —— B 的成本一分没少，只是那时才有理由付。

**被推翻的**（同一次设计里改过主意的，记下来免得下次重走）：

- "连线用直线" → **平滑贝塞尔曲线**。正交折线必须避让图形，而避让是 dagre / mxGraph 存在的全部理由，手写这一层不比组件本身小。
- "agent 出图以后再说" → **v1 就做**。数据平面（`agent.tools`）已经落地，接现成的比自己发明协议便宜。
- "多选/框选 v1 要做" 没被采纳；"连线标签"也没做，但 `label?` 字段先留。

## 4. 接口与数据

**桥方法 / Tauri 命令**：**一个都不加。** 只用现成的 `storage.get/set`、`theme.get`、`lang.get`。这是这个组件最值钱的一条 —— 平台不需要为它长大。

**权限**：`storage`（图形数据）+ `agent:tools`（agent 能往里塞图形）。就这两条。

**工具契约**（清单 `agent.tools`，名字由平台拼成 `widget.lattice.diagram.<工具>`）

| 工具 | 参数 | 返回 |
| --- | --- | --- |
| `draw` | `{ nodes: [{ label, kind? }], edges: [{ from, to }] }` | `{ ok, nodes, edges }` |
| `add` | 同上，追加到现有图 | 同上 |
| `read` | `{}` | `{ nodes: [{ label }], edges: [{ from, to }] }`，**不回坐标** |

- `kind` 只认 `box` / `circle` / `diamond`，缺省 `box`。文本和连线由组件补 —— 让模型选"这是不是文本框"没有意义。
- `from` / `to` 是 `nodes` 的**下标**（0 起）。
- 上限：**24 个节点 / 40 条边 / 每个标签 40 字符**。超了**拒绝**并回一句能读懂的话 —— 不截断，截断等于替它决定后半截不重要。
- 一次调用 = **一步撤销**。`draw` 会先清空，但清空前那份在撤销栈里，`Ctrl+Z` 能整体退回。
- 排版在组件里做（确定性纯函数）：按入边分层、从左到右；**输入里有环**（A→B→A）时退回"按输入顺序分列"，不报错。

**落盘格式**（键 `diagram`；`storage` 是键级写 + `.bak` 兜底）

```json
{
  "version": 1,
  "nodes": [
    { "id": "n1", "kind": "box", "x": 24, "y": 24, "w": 120, "h": 48, "text": "Platform", "tone": "accent" }
  ],
  "edges": [{ "id": "e1", "from": "n1", "to": "n2" }],
  "view": { "x": 0, "y": 0, "zoom": 1 }
}
```

- 坐标是**世界坐标**，卡片只是视口；`view` 只记平移和缩放。
- `tone` 只有 `accent` / `neutral` / `warn`，真实色值从 `theme.get` 取 —— 存死色值切到浅色主题会瞎。
- 端点位置**不存**，由 `from` / `to` 两个图形的几何算出来。
- `version` 缺失或不认识 → **当空图显示，但不落盘**。读坏不等于没有数据，绝不能用空图覆盖真数据。

**要改的文件**

- `public/widgets/lattice.diagram/`：`manifest.json` / `index.html` / `style.css` / `widget.js` / `diagram-core.js`
- `tests/diagram.html`（纯逻辑）、`tests/help.html` 的对账（它会读清单，新组件自动被要求有 `help` + `changelog`）
- `public/widgets/index.json`（`npm run widgets:index`）
- 文档：`docs/ROADMAP.md` 一行、`GLOSSARY.md` 三个词（已写）

## 5. 失败模式

| 症状 | 原因 | 正确行为 |
| --- | --- | --- |
| 拖一个框，卡片卡一下，桌面别的东西也跟着抖 | 每次 `pointermove` 都 `storage.set`，整块写盘 | 拖动中只改内存，松手写一次；其余改动 400ms 防抖 |
| 打开时图是空的，原来的图没了 | 读失败（权限被拒 / IPC 挂）被当成"没有数据"，把空图写回去 | `null` 和 reject 分开：reject 只把界面标成"没读到"，**一个字节都不写** |
| 在桌面挪了框，画布这边一保存就把它改回去 | 两个宿主各持一份内存副本 | 收到 `store-changed` 就重读；**有未落盘改动时先不重读**，落盘之后再收 |
| agent 说"画三个服务"，屏幕上闪一下全没了 | `draw` 先清空再画 | 清空和重画在同一次状态变更里完成；整次调用只进撤销栈一步 |
| agent 传 200 个节点，卡片卡死 | 没有上限 | 超过 24 / 40 直接拒绝；**不截断** |
| agent 给的图里有环，画不出来 | 长路径分层在环上算不出来 | 检测到环退回"按输入顺序分列"，图照样出来 |
| 缩放之后点不中图形 | 命中检测用屏幕坐标，渲染用世界坐标 | 命中一律先 `screen → world`；这层是纯函数，`tests/diagram.html` 钉住 |
| 平移状态下双击空白，框加到了别处 | 加图形时用了鼠标屏幕坐标 | 同样先换算成世界坐标 |
| 标签挤成两行、盖住箭头 | 文本框宽度按字数估 | 中文 1 字 ≈ 14px、英文 ≈ 8px 加 padding，最小 80×40；超过 3 行省略，完整文本进 `title` |

## 6. 验收

| 文件 | 条数 | 钉住什么 |
| --- | --- | --- |
| `tests/diagram.html` | ~90 | 世界↔屏幕变换、命中检测、端点与贝塞尔控制点、`applyOps` 的增删改、上限拒绝、有环时的分层退回、`version` 不认识时不落盘 |
| `.scratch/diagram-probe.html` | 布局探针 | 五种图形 + 三条曲线在 420×300 与 260×180 下不溢出，右上角 120×28 窗饰不压内容 |

**手工验一次**：桌面上画一张（加框 → 双击改字 → 连线 → 拖框看线跟着走 → 缩放 → `Ctrl+Z` 三次 → 关窗重开还在）；让 assistant 说"把这三个服务画成一条链"，同一句话跑两次必须一模一样（确定性）；最后在两个宿主里同时开这张图，确认"有未落盘改动时不会被另一边拽回去"。

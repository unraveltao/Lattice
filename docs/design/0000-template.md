# 0000 —— 标题（动词 + 对象，别写"关于……的思考"）

> 用法：整段引用（以 `>` 开头的行）都是提示，填完删掉。填不满的段落不要留空标题，删掉那一段并说明为什么不需要。
> 全文目标两页以内。超过两页，这件事该拆。

## 1. 问题

> 一句话：不做会怎样。具体到"谁、在什么场景下、看到什么坏结果"。
> 不许写"提升体验""更好的架构"这类没有主语的句子。

## 2. 候选

> 至少两个，各自**换掉**什么、代价是什么。其中至少一个应该是你本来想选的。
> 用表格，一列一个方案，别写成三段散文。

| --- | --- | --- | --- |
| 做法 | | | |
| 换掉什么 | | | |
| 新增什么 | | | |
| 代价 | | | |

## 3. 决定

> 选哪个，为什么。**代价必须写具体**：是"多一个依赖"、"多一次 IPC"、"用户要重装"，不是"暂时不完美"。
> 顺便写一句：什么情况下这个决定该被推翻（将来的人据此判断要不要重开）。

> 只写跨进程 / 跨层 / 落盘的那一条。方法名、参数、返回、错误码、旧数据怎么迁。
> 不写内部函数怎么拆——那是实现，改起来不要钱。

**桥方法 / Tauri 命令**


**落盘格式与迁移**

> 没有持久化就写"无"。

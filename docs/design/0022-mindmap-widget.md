# 0022 —— 在组件里写一张思维导图（`lattice.mindmap`）

## 1. 问题

`lattice.diagram` 能画框连线，但它是**自由画布**：位置是用户手工摆的，结构只存在于"看起来像"里。想理清一件事的层次 —— 拆任务、列大纲、把一段话压成结构 —— 每加一个想法都要自己拖到合适的位置，改一次从属关系（"这一支其实挂在那一支下面"）要挪一堆框。

**坏结果**：思考的过程要用排版来维护；让 assistant 生成一张图，它得同时编造内容和坐标，同一句话跑两次出来的图不一样。

## 2. 候选

**数据模型**（这张表决定其余一切）

| | A：存树，位置算出来（选中） | B：存坐标，和 diagram 一样 | C：只存一段大纲文本 |
| --- | --- | --- | --- |
| 做法 | 节点是 `{ id, text, collapsed, children[] }`，布局是纯函数 | 每个节点带 `x` / `y`，拖动改坐标 | 整份数据就是缩进文本，每次打开重新解析 |
| 换掉什么 | 自由摆放 | 结构不可查询，只能靠坐标猜 | —— |
| 新增什么 | 布局 / 命中 / 结构操作三组纯函数 | —— | 一个解析器（本来也要写，见 §4） |
| 代价 | 不能手工摆位；节点宽度必须测量 | agent 得编造坐标；改结构 = 重排 | 折叠状态、视图位置没处放；节点没有 id，无法被引用 |

**布局方向**

| | A：右向生长（选中） | B：放射状 | C：根居中、左右镜像 |
| --- | --- | --- | --- |
| 做法 | 一列一层，从上往下堆叶子 | 按角度铺开 | 左右各一半，镜像排 |
| 换掉什么 | "思维导图该有的样子" | —— | —— |
| 代价 | 叶子多时图很高（30 个叶子 × 28px = 840px） | 三层以上标签在 260px 宽里必然相撞，避让逻辑不比组件本身小 | 布局、对齐、贝塞尔镜像各写一遍，代码翻倍 |

## 3. 决定

**决定**：A + A —— 存树、位置算出来；右向生长；导出走剪贴板。

**代价**（具体）：

- **不能手工摆位**。想要"位置由我定"的人要的是 `lattice.diagram`，不是这个。两个组件同时在目录里，选错的那个会让人以为"思维导图不能拖"。
- **叶子多了图很高**，只能缩放和平移，卡片不会自己长大。折叠是唯一的解法，所以折叠必须顺手（`←` 一键）。
- **导出是"复制一段文本"，不是"存一个文件"**。沙箱是 `allow-scripts allow-forms`，没有 `allow-downloads`，`Blob` + `<a download>` 会被拦；`shell.open` 只收 http/https。用户在卡片里找不到"另存为"，所以 `help` 里要正面写清"复制 → 粘到你想要的地方"，而不是让人找。
- **多要一条权限 `clipboard:write`**。一个纯本地的画图组件要剪贴板权限，得在 `help` 里说清是干什么用的 —— 否则用户看到的是一串看不懂的授权项。

**什么时候该推翻它**：叶子常态超过 30 个（那时该做镜像双列或虚拟滚动，而不是继续压字号）；或者平台加了文件导出桥方法（`file.save`），那时导出应该改走它，剪贴板退成次要入口。

**被推翻的**（同一次设计里改过主意的）：

- "放射状才是思维导图的样子" → **右向生长**。放射状在 420×300 里撑不到第三层，而第三层正是思维导图开始有用的地方。
- "拖拽改从属关系 v1 要做" → **v1 只做键盘**（`Tab` / `Shift+Tab` / `Alt+↑↓`）。卡片最小 280×200，"拖到两个节点之间"的命中判定在这个尺寸上误差比意图大；拖拽放进 v1.1，数据结构已经支持（换父节点就是换 children 数组）。
- "agent 传一棵 JSON 树" → **传缩进文本**。WIDGET_SPEC §3.6 的参数只能是 `string` / `number` / `boolean`。这条和 0008 撞的是同一堵墙。
- "自己发明一个 `.mm` 文件格式" → **不发明**。Markdown 大纲 / Mermaid / OPML 三种现成的，别的工具能读，用户不用为这个组件换一套工具链。

## 4. 接口与数据

**桥方法 / Tauri 命令**：**一个都不加。** 只用现成的 `storage.get/set`、`clipboard.write`、`theme.get`、`lang.get`、`config.get`。和 0008 同一条：平台不该为组件长大。

**权限**：`storage` + `agent:tools` + `clipboard:write`。

**大纲文本 —— 一个格式，三个用途**（agent 输入、剪贴板导出、人手工粘贴导入）

```
Project
  Design
    Layout
    Export
  Build
```

- 一行一个节点，**行首缩进决定层级**。用栈解析：一行的父节点是"前面最近的、缩进更小的那一行" —— 不猜步长，2 / 3 / 4 空格都对。
- 行首的 `- ` `* ` `+ ` `# ` 一律剥掉（模型爱写列表，Markdown 导出也带它，两边因此能互相喂）。
- 一个 tab 当 **2 个空格**。混用空格和 tab 的输入按展开后的宽度算，不报错。
- 空行忽略；行尾空白去掉。
- **多行顶层**：第一个顶层行当根，其余顶层行收成根的子节点，返回值里带 `roots` 说明发生了这件事（思维导图只有一个根，直接拒绝会让模型反复重试）。
- 上限：**200 个节点 / 深度 12 / 单行 80 码点**。超了**拒绝**并回一句能读懂的话 —— 不截断。
- 导出：折叠的节点**照样导出整棵子树**（导出的是内容，不是视图）。节点宽度只影响显示，不影响导出（`title` 里存全文）。

**工具契约**（名字由平台拼成 `widget.lattice.mindmap.<工具>`）

| 工具 | 参数 | 返回 |
| --- | --- | --- |
| `draw` | `{ outline }`：整张替换 | `{ nodes, depth, roots }` |
| `append` | `{ outline, under? }`：`under` 是节点文本（首个精确命中），缺省挂到根 | `{ added, nodes }` |
| `read` | `{}` | `{ nodes, depth, outline? }` —— `outline` 只在序列化后 ≤3500 字符时给 |

- 一次调用 = **一步撤销**（`draw` 清空前那份在撤销栈里）。
- `read` 不硬塞整份：超过 3500 字符只回计数，让模型改用别的办法 —— 平台那边超过 4000 是**拒绝**（`too-big`），半截大纲比没有更糟。

**落盘格式**（键 `mindmap`；`storage` 是键级写 + `.bak` 兜底）

```json
{
  "version": 1,
  "root": {
    "id": "n1", "text": "Project", "collapsed": false, "tone": "accent",
    "children": [{ "id": "n2", "text": "Design", "collapsed": false, "children": [] }]
  },
  "view": { "x": 0, "y": 0, "zoom": 1 }
}
```

- **位置不存**，由 `layout()` 从树算出来；`view` 只记平移和缩放（和 0008 同一套语义）。
- `id` 只在本文件内有意义（`n1..nN`），加载时扫一遍算 `nextId`，不单独存计数器。
- `tone` 存名字（`accent` / `neutral` / `warn`），色值从 `theme.get` 取 —— 存死色值切浅色主题会瞎。
- `version` 缺失或不认识 → **当空图显示，但不落盘**（读坏不等于没有数据）。

**布局（纯函数，`measure` 注入）**

```
layout(root, { measure, row = 28, colGap = 40, pad = 16 })
  → { nodes: [{ id, text, tone, depth, x, y, w, h, center, hidden, hasChildren }],
      links: [{ from, to, d }], bounds: { w, h }, rows }
```

- 每个叶子占一行 28px；父节点的 `y` 是子树跨度的中点；`x = pad + Σ(每层最宽节点 + colGap)`。
- 节点宽度 = `clamp(measure(text) + 16, 64, 220)`。`measure` 由调用方传（真机用 canvas `measureText`，测试传桩）—— 纯逻辑里不碰 DOM，也不用猜"中文 14px、英文 8px"。
- 连线是父节点右边缘到子节点左边缘的贝塞尔，控制点落在水平中点。
- 折叠的节点画一个 `+N` 角标（`hidden` 就是 N），子树只占一行。

## 5. 失败模式

| 症状 | 原因 | 正确行为 |
| --- | --- | --- |
| 打开时图是空的，原来那张没了 | 读失败（权限被拒 / IPC 挂）被当成"没有数据"，把空图写回去 | `null` 和 reject 分开：reject 只把界面标成"没读到"，**一个字节都不写** |
| 在桌面改了一个字，画布那边一保存就把它改回去 | 两个宿主各持一份内存副本 | 收到 `store-changed` 重读；**有未落盘改动时先不重读**，落盘之后再收 |
| 中文输入法里按回车，词没上屏却多出一个节点 | 没判 `isComposing` | `compositionstart` / `compositionend` 期间不响应 `Enter` / `Tab`，输入法自己的回车才算数 |
| 按 `Tab` 加子节点，卡片跳一下、选中的是别人 | 加完没同步选中和视图 | 加完立即选中新节点；新节点在视口外时滚过去（不是整张 fit） |
| 30 个叶子，一打开只看见中间几个字 | 每次加载都 fit，或者从不 fit | 存过 `view` 就照存的来；没存过才 fit 一次 |
| 折叠再展开，滚动位置跳了 | 重新布局后没保持焦点 | 展开 / 折叠后把选中节点滚回视野 |
| 复制按钮点了没反应，也没提示 | `clipboard:write` 没授，或系统剪贴板被别的进程占着 | 失败必须可见（一行"没复制成功：剪贴板权限没开"）；成功才换成"已复制" |
| 粘进 XMind 是乱码 | OPML 少了 XML 声明或编码 | 固定输出 `<?xml version="1.0" encoding="UTF-8"?>`，文本转义 `& < > "` |
| 粘进 Mermaid 渲染失败 | 节点文本里有 `(` `)` `[` `]` `:` 或换行 | 序列化时换成 `-` / 空格；Mermaid 里括号就是语法 |
| 长节点显示被省略，导出也少了后半截 | 导出走了"显示用的截断文本" | 导出永远走数据；完整文本进 `title`，宽度截断只影响画 |
| agent 传 200 行，卡片卡死 | 没有上限 | 超过 200 / 深度 12 / 单行 80 直接拒绝，**不截断** |
| agent 的大纲有三个顶层行，图变成三棵独立的树 | 导图只有一个根 | 第一个当根，其余收成子节点，返回值里报 `roots` |

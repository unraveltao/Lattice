# 0009 —— 两个模式：内部 / 完全访问（Full access，推翻 0006 的"定时授权"）

> 用户的原话：**"开全权（我希望有个开关可以打开）……它有两个模式，一个只是管理内部的，一个是管理全部的，像我一样。"**
> 0006 定的是"一次 30 分钟的定时授权，到点自动关，没有开关"。它防住了"忘在 `auto` 上"，
> 却没回答"我就是要把它当正常 agent 长时间用" —— 每半小时回来点一次，等于把它当实验品。
> 这一份把 0006 的**定时**换成**一个能一直看见、随时能切的模式开关**。
>
> 后来用户又要一样东西：**"这个按钮开关变成 DSH 的 full access 功能"**（DSH = 这个仓库的开发
> 环境本身，它的 full access 是一道带勾选框的风险确认）。所以第二种模式在界面上就叫
> **「完全访问 / Full access」**，启用它的那一下走 DSH 那道确认的形状。**存的值不动**：
> `assistant.json` 里仍是 `mode: "internal" | "everything"` —— 字面量是历史，改它要迁移文件，
> 换不来任何东西。改名只发生在界面与文档上。

## 1. 问题

0006 之后摆着的事实是：用户要的不是"这半小时随便动"，而是"**这个助手有两种人格**"——

- **内部**：管桌面。挪组件、改主题、开关手、装好的组件互相通气（组件声明的工具）。它不该碰 `C:\` 上的任意文件，因为那是"平台的事"之外。
- **完全访问**：像我这样。读文件、跑命令、抓网页、点键鼠 —— 一个正常的 agent，而且**少问几步**。

而"开关"这个词本身就是答案：用户要的是**一个状态**，不是一个倒计时。倒计时解决的是"我忘了关"，
但代价是"我一直被打断"。这两件事可以用**可见性**换掉，不必用中断换。

## 2. 候选

| | A：定时授权（0006） | B：持久模式开关 | C：每轮开场选一次 |
| --- | --- | --- | --- |
| 长任务 | 每 30 分钟打断一次 | 不打断，一直在那个模式下 | 每轮都要选，最烦 |
| 忘记关 | 不存在 | 存在 | 不存在 |
| 心智模型 | "一次授权" | **"两种模式"（用户原话）** | "每轮临时决定" |
| 代价 | 把它当实验品 | 需要一个一直看得见的标识 | 会话文件多一个字段 + 每次多点一下 |

选 B。风险用**常驻可见 + 一次性确认 + 审计**兜，不用中断兜 —— 这也是桌面软件里"模式"的通用做法（代理开关、飞行模式）。
C 被否得再补一句：它把"我刚才干到哪了"和"我现在是什么模式"混在一份文件里，而这两个问题的生命周期不一样。

## 3. 决定

**一个开关，两种模式，存盘。**

| | 内部（默认） | 完全访问（Full access） |
| --- | --- | --- |
| 工具表 | 8 个桌面动作 + 组件声明的工具 + **你拨开的那几组手**（默认六组全关） | 再加六组手（文件 / 命令 / 网页 / 屏幕 / 键鼠 / MCP），不管你存的是什么 |
| 审批 | 照 `approvalMode`（默认每次问） | **不问**（问就不叫完全访问了） |
| 六组开关 | **照存的开关**：内部 = 你开哪几组就有哪几组 | 忽略存的开关，**一律算开**（`effectiveHands` 强制）；启用那一刻顺手把六个值也拨开，见下 |
| 预算 | 24 步 / 5 分钟 / 20 万 token | **一模一样**（模式是权限，不是预算） |

- **模式管"要不要问"，开关管"能不能"**。内部不是"一只都不给"，而是"给的就是你在面板上
  拨开的那几组"。
- **启用完全访问 = 一道确认，两件事一起做**（`confirmEverything`）：先把六组拨开
  （`grantAllHands`，只写那六个开关），再写 `mode`。顺序有意 —— 按完之后面板上那六个勾
  就是他真的拿到的权力，看得见、也收得回；只写模式的话，用户会看到"模式说全开、六个勾全空"，
  分不清到底给了什么。开关没存上就不切模式（一步都没落地比半步落地好收拾）。
- **那道确认的形状照 DSH**（用户点名要的）：
  标题「Enable Full access?」+ 一段风险（会读写任何地方的文件、跑命令、取网页、截屏、动键鼠、
  调 MCP 服务，**都不再问**；下面六组会一起拨开）+ 四条硬线 + 一句"想收回去点一下就关，
  关掉从来不问" + **必须勾上的「我明白风险，继续」**（没勾上，Enable 那颗是灰的）+
  Cancel / Enable Full access。DSH 那段原话缺三样东西，这里补齐：**具体会做什么**、
  **什么它仍然做不到**、**怎么退出来**。
- **它得塞得进最小的小窗**：320×420 下，英文那道确认有 381px（风险段 + 四条硬线 +
  勾选框 + 两颗按钮），而面板是一个 flex 列 —— 它要是 `flex: none`，"不够高"这件事就全由
  下面的对话区和输入框承担，被顶出窗框的正好是那两颗按钮（实测底边多出 50px）。所以它是
  `flex: 0 1 auto` + `min-height: 0` + `overflow-y: auto`：空间不够时它先让，让不下的部分
  在框里滚，输入框和按钮永远够得着。判据是"**一屏放不下时先让内容滚，别把按钮推出可视区**"。
- **两个入口，同一道确认**：输入框左下角那颗警示色药丸和手那一段那颗走同一个
  `requestFullAccess()` —— 一个状态，一个确认，不许出现第二条不用点头的路。
  （药丸原来在模式条右端，2026-10-25 挪到输入框那一行的最左，理由见 §7。）
- **关掉不问，也不收手**：从完全访问退回内部只写 `mode`，六个开关原样留着 —— 手还在，
  问话回来（"能不能"与"问不问"本来就该分开）。想把能力也收掉，按「全关」那颗：
  它同时停这一轮、关六组、把模式也退回内部。
- **只读档压住时不许启用**：`readonly` 优先（`effective` 为 false），那道确认里会写明
  "只读档开着，而且它优先 —— 先把审批档换成 Ask 或 Automatic"，Enable 那颗也是灰的。
  否则用户勾完框、按完按钮，什么都不会变。
- 存进 `assistant.json` **v4**：`mode: "internal" | "everything"`。坏值落 `internal`
  —— 和所有坏值同一条：**不许扩大权限**。
- **常驻可见**：面板顶部一条模式条（完全访问用警示色 + 一行
  "Files, commands, the web, the screen, input and MCP servers. Approvals are not asked."），
  窗口标题栏那个点跟着变色。切换本身进审计：`assistant.mode` 一条。
- 四条硬线沿用 0006 §3（不因为换成开关就松）：
  1. 装 / 卸 / 授权 / 钉钥匙**不在工具表里**；
  2. 改平台自身配置（`assistant.json` / `mcp.json` / `state.json` / `skills/**`）**永远要问**；
  3. 组件借手那一轮（`caller === "widget"`）拿不到 `everything`；
  4. agent 的 HTTP 端点不受影响。
- 审计：每次调用行尾 ` · everything`；**写不进去就不执行**（fail-closed），别的模式照旧。
- 和审批档的关系：模式管"能碰什么"，档管"要不要问"。`everything` 下不问，但 **`readonly` 仍然优先**
  —— 用户在只读档里，模式条显示"被只读档压住"，调用照拒。
  **不做"切模式顺手把档改掉"**：一个设置不该偷偷改另一个设置（0006 也守着这条）。

## 4. 接口与数据

```json
// assistant.json v4（v3 读到就地升级：mode = "internal"，手全关，不替用户开门）
{ "version": 4, "mode": "internal", "activeId": "…", "hands": { … }, "approvalMode": "ask", "workspace": "", "profiles": [ … ] }
```

```
assistant_mode()                 → { mode, effective }     // effective 已经算过 readonly 压制
assistant_mode_set(mode)         → 同上（写盘 + 审计一条）
```

- Rust：`llm::hands_state` 多一个 `mode`；`hands::run` 用 `mode == "everything"` 判（**替换**
  `full_access_view` / `full_access_overrides` / `assistant_full_access*` 那一套 —— 0006 的骨架还没接线，删掉没有兼容负担）；
  `shape_of` 的后缀换成 ` · everything`。
- 前端：`runtime/hands.ts` 的 `effectiveHands(hands, mode)` / `modeIgnoresSwitches(mode)` /
  `grantAllHands(hands)`（只写开关那六个值，由那道确认调用 —— 它自己**不写 mode**）；
  `runtime/assistant.ts` 的 `approvalFor(name, mode, ctx)` 里 `ctx.fullAccess` 改名 `ctx.everything`；
  `AssistantPanel.tsx` 模式条 + `requestFullAccess` / `confirmEverything` 那道确认
  （勾选框 `riskAck`、只读档锁 `fullAccessBlocked`）+ 手那一段（`Enable Full access` / `Turn all off`）——
  完全访问期间六组**画成勾且锁上**（拨了不生效的框比不给拨更糟）；
  `runtime/i18n/assistant.ts` 新文案（`Full access` / `Enable Full access` / 风险段 / 勾选框 / 关掉）。

## 5. 失败模式

| 症状 | 原因 | 正确行为 |
| --- | --- | --- |
| 忘了还在完全访问 | 开关是持久的（这是它的价格） | 启动后第一次打开面板时，若存的是 `everything` 就提示一次；之后靠常驻模式条，不再打断 |
| 以为关掉完全访问就安全了，但它还能读文件 | 关掉**不收手**（手是用户给的，一个设置不该改另一个）；或会话里正在飞的一轮拿的老工具表 | 每次调用现查模式（Rust 那一层）；关掉只把"要不要问"还回来，要收能力按「全关」那颗 |
| 以为「内部」等于一只新手都没有 | 第一版文档就这么写的，代码一直是照开关 | 内部 = 你拨开的那几组，面板上手那一段写明它，模式条悬停也写明 |
| 勾了框、按了 Enable，什么都没变 | 只读档压着完全访问 | 确认框里写明"只读档优先，先把审批档换成 Ask 或 Automatic"，并且那颗按钮是灰的 |
| 只读档 + 完全访问 | 两个状态冲突 | `readonly` 优先，模式条写明"被只读档压住" |
| 文件被手改成乱码 | 坏值 | 落 `internal`，手全关；**绝不**因为一个坏值变成全开 |
| 审计写不进去 | 磁盘 / 权限 | 完全访问下 fail-closed（`code: "audit"`），内部模式照旧 |
| 组件借手那一轮想要完全访问 | 那条路没有确认条 | 硬拒：`caller === "widget"` 一律 `internal` |

## 7. 修订（2026-10-25）：入口挪到输入框左下角

用户看过真机之后提的：「这个权限功能改到左下角，和这个相似，图标和字体颜色也可以一样」
（附的参考图：圆圈叹号 + 一句话 + 一个箭头，整颗是警示色的药丸）。

改的是**位置和形状**，不是判据：

- 原来那颗在模式条右端，和模式名挤同一行 —— 那一行说的是"我现在是什么状态"，
  按钮说的是"我要变成另一个状态"，两件事共用一个 30px 的高度；而且它在标题区，
  离"我要让它放手干"这个念头很远。
- 现在常驻在**输入框那一行的最左**，和「发送」同一行：放权与发话是同一类动作。
  形状换成药丸（`--lattice-danger` 的字 + `danger-soft` 的底 + 圆圈叹号 + 箭头），
  完全访问时同一颗变成「Turn off full access」，边框实心。
- 确认面板跟着入口走：对话态贴着输入框渲染（按它就在它上面展开，不在屏的另一头），
  设置态仍贴在模式条下面（那颗按钮在手那一段的头里）。**一份 JSX，两个位置**。
- 模式条本身还在（§3 的「常驻可见」不变），只是**只剩状态**：内部模式补了一句
  "Only the hands you switched on." —— 挪走按钮之后它那一格是空的，而 §5 第一条
  误解就是"内部 = 一只新手都没有"。

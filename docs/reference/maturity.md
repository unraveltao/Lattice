# 功能成熟度

> 这一页只回答一句话：**我现在能不能靠它。**
>
> 版本走到哪在 [`ROADMAP`](../ROADMAP.md) 的进度总览，缺的那一项怎么算验完在 [`known-gaps`](./known-gaps.md) 的 8.1，打算怎么做在 [`design/`](../design/)。这里只给**一个词**。
>
> **一个面只有一个词。** 四个词之外的形容词（"基本可用"、"部分支持"、"应该没问题"）不许用 —— 那是在躲这个问题，而躲开的代价由读的人付。

## 一、四个词

| 词 | 判据 | 你能指望什么 |
| --- | --- | --- |
| **已实现** | 真机上走过，而且 [`known-gaps` 8.1](./known-gaps.md) 里没有它 | 坏了就是 bug，去开 issue |
| **未验证** | 代码和断言都在，8.1 里有一行 —— 缺的是一次真机 / 另一台机器 / 真硬件 | 大概率是对的；不对劲先去 8.1 找有没有你这一行，别急着当新 bug 报 |
| **实验中** | 能开，但默认关、行为还会变、不承诺兼容 | 试可以，别当地基 |
| **计划中** | 只有设计或待办，没有能用的代码 | 现在用不了 |

判据只有一句：**发布出去的安装包能不能做到。** 做不到的，代码写了多少都不算"已实现"。

三条容易搞反的：

- **"未验证"不等于"有问题"。** 它说的是"断言全绿、逻辑被钉住了，只是没人在真机上走过那一遍"。这类问题的形状通常是"某个数字不对"或"某个手势没反应"，不是崩溃 —— 而且 8.1 每一条都写着怎么算完。
- **"默认关"不等于"实验中"。** 手六组、agent 端点、完全访问都默认关，但它们是按"已实现"的要求做的 —— 关着是安全默认，不是半成品。
- **"已实现"不等于"永远不变"。** 界面和字段还会改，但"改"是正常演进，和"它现在能不能用"是两件事。

**这一页可以被核对。** 随便挑一行写着"已实现"的，去 8.1 搜一遍：搜到，就是这一页错了；反过来，8.1 里有一行、下面的表里却找不到对应的面，那是这一页漏了。

**同一块能力可以拆成两行，但行名要写清是哪一半** —— 主链路和收尾是两个面（"终端组件"和"终端的收尾四处"），"终端"和"终端"不是。拆的理由是让人一眼看出"能用"和"还剩什么"，不是为了给同一个东西挑一个好看点的词。

### 实验中

**现在是空的，空着本身是信息。**

这个仓库不发"默认开着、随时会变"的东西：没验完的一律默认关（手六组、agent 端点、完全访问都要显式打开），验完的才默认开。所以"能开"和"能用"在这里是同一件事，没有中间态。

什么时候会有第一个：某件东西**必须在没验完之前就默认给出去** —— 那时它进这一栏，同时 `design/` 里要有一份 `draft` 说清为什么现在就得给。没有那份 draft 就进这一栏，等于把"我们还没想清楚"写成了状态。

## 三、这些不是缺口，是取舍

有几件事**永远不会变成"已实现"**，别等它修：磨砂底板透不出后面的窗口、没有服务端所以评分不汇总、只有 Windows、画布预览只是近似。它们是有意的，每条都写着试过什么、代价是什么 —— 逐条在 [`known-gaps` 8.3](./known-gaps.md)，用户视角在 [FAQ](../FAQ.md)。

## 四、什么时候改这一页

发版时改，和 README 那两张表一起（[`docs/README.md` 第五节](../README.md)）。

判据只有一条：**8.1 里划掉一行，这里对应的那一行就从"未验证"挪到"已实现"。** 反过来也成立 —— 新加的东西只要没在真机上走过，先写"未验证"，别先写"已实现"再等有人来验；那等于把待办写成完成，而这张表存在的全部意义就是让人分得清这两件事。
